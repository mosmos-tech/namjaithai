# SOS ผ่าน SMS (TF-36)

ผู้ประสบภัยที่ไม่มีเน็ตส่ง SMS ขอความช่วยเหลือได้ ระบบจะสร้างเคสและตอบรหัสเคสกลับทาง SMS

```
มือถือผู้ประสบภัย ──SMS──▶ มือถือ Android (ซิมของทีม + แอป httpSMS)
                                   │ webhook (HTTPS, เซ็น JWT)
                                   ▼
                        POST /api/sms/inbound ──▶ create_sos_case() (กติกาเดียวกับฟอร์มเว็บ)
                                   │
                    ตอบกลับผ่าน httpSMS API ◀──┘  "รับเรื่องแล้ว รหัสเคส FL-..."
```

## รูปแบบข้อความ

```
SOS <ประเภทเหตุ> [ระดับน้ำ] <lat>,<lng> [P5] [B1] [C0] [E2]
```

| ส่วน       | ความหมาย                                                                | ตัวอย่าง       |
| ---------- | ----------------------------------------------------------------------- | -------------- |
| `SOS`      | ต้องขึ้นต้นด้วยคำนี้                                                    | `SOS`          |
| ประเภทเหตุ | ตอนนี้รับเฉพาะ `FLOOD` (ไม่ใส่ = `FLOOD`)                               | `FLOOD`        |
| ระดับน้ำ   | ไม่บังคับ: `ROOF` `FIRST_FLOOR` `WAIST_CHEST` `ANKLE_KNEE` `SURROUNDED` | `ROOF`         |
| พิกัด      | ละติจูด,ลองจิจูด (บังคับ)                                               | `13.75,100.50` |
| `P`        | คนทั้งหมด                                                               | `P5`           |
| `B`        | ผู้ป่วยติดเตียง                                                         | `B1`           |
| `C`        | เด็กเล็ก                                                                | `C0`           |
| `E`        | ผู้สูงอายุ                                                              | `E2`           |

- ตัวพิมพ์เล็ก/ใหญ่ได้หมด ช่องว่างกี่ช่องก็ได้ ส่วนหลัง `SOS` เรียงลำดับไหนก็ได้
- จำนวนที่ไม่ใส่ = 0 · ไม่ใส่จำนวนเลย = ผู้ส่ง 1 คน (ไม่ปฏิเสธคำขอเพราะลืมใส่จำนวน)
- **ไม่มีสีความเร่งด่วน** — เซิร์ฟเวอร์คำนวณด้วย `computeTriage()` เหมือนฟอร์มเว็บ
- ข้อมูลที่ SMS ไม่มี: ชื่อ = "ผู้แจ้งทาง SMS", จุดสังเกต = "แจ้งทาง SMS", ถือว่าออกเองไม่ได้ (over-triage)
- เหตุประเภทอื่นมีคำถามบังคับที่ SMS ถามไม่ได้ → ตอบให้โทร 1669 / 191 / 199 (TODO(TF-54))

ปุ่ม "ส่งทาง SMS" บนหน้าจอ "บันทึกไว้ในเครื่องแล้ว — ยังไม่ถึงทีมกู้ภัย" สร้างข้อความนี้จากร่างฟอร์มให้อัตโนมัติ
(`formatSmsSos()` ใน `src/lib/domain/sms-format.ts` · ตัวอ่าน `parseSmsSos()` ใน `sms-sos.ts`)

## การตอบกลับ

| ผล                            | ตอบ                                      | หมายเหตุ                                                 |
| ----------------------------- | ---------------------------------------- | -------------------------------------------------------- |
| สร้างเคสแล้ว                  | รหัสเคส + ลิงก์ติดตาม + ลิงก์ `/privacy` | ตอบเสมอ                                                  |
| เบอร์นี้มีเคสเปิดอยู่         | รหัสเคสเดิม ไม่สร้างใหม่                 | บันทึก `case_events` = `SMS_REPEATED` (ไม่เก็บเนื้อความ) |
| ผิดรูปแบบ                     | วิธีส่งที่ถูก + ตัวอย่าง + สายด่วน       |                                                          |
| ส่งบ่อยเกิน (5 เคส/ชม./เบอร์) | ให้รอหรือโทรสายด่วน                      |                                                          |
| ระบบขัดข้อง                   | ให้โทรสายด่วน                            |                                                          |

คำตอบที่ไม่ใช่ "สร้างเคสแล้ว" ส่งได้ไม่เกิน **1 ครั้งต่อเบอร์ต่อ 10 นาที** กันเปลืองค่า SMS และกันวนลูปกับเครื่องที่ตอบอัตโนมัติ
เบอร์ที่ไม่ใช่เบอร์ไทย (เช่น SMS โฆษณาของเครือข่าย) ไม่ตอบ

**ความยินยอม:** คนพิมพ์ SMS เองไม่เคยเห็นหน้ายินยอม เคสจาก SMS จึงบันทึก `consent_version = SMS-2026-11-08`
แยกจากฟอร์มเว็บ ไม่บันทึกความยินยอมข้อมูลสุขภาพ และ SMS ตอบกลับมีลิงก์ `/privacy` เสมอ

**ความเป็นส่วนตัว:** `sms_inbound_messages` ไม่เก็บเนื้อความ เก็บแค่เบอร์ พิกัดที่อ่านได้ และผล
แอดมินอ่านได้อย่างเดียว · pg_cron `tf36-sms-inbound-retention` ล้างเบอร์และพิกัดของแถวที่เกิน 90 วันทุกคืน
และบันทึก `audit_logs` (`SMS_PII_PURGED`) — TODO(TF-44) รวมกับงานล้างข้อมูลของ TF-44

ทีมกู้ภัยเห็นป้าย **"พิกัดจาก SMS"** ในหน้ารายการและหน้ารายละเอียดเคส เพราะพิกัดอาจพิมพ์เองและไม่รู้ความแม่นยำ

## ตั้งเครื่อง gateway

ต้องมี: มือถือ Android 1 เครื่อง (เปิดเครื่องและต่อเน็ตไว้ตลอด) + ซิมแยกที่ส่ง/รับ SMS ได้

1. ใส่ซิม แล้วลงแอป httpSMS จาก [httpsms.com](https://httpsms.com) (ลิงก์ Play Store / APK อยู่ในหน้าเว็บ)
2. ล็อกอินเว็บ httpsms.com ด้วยบัญชีของทีม แล้วล็อกอินแอปด้วยบัญชีเดียวกัน ใส่เบอร์ซิมในแอป
3. ในแอป Android: ปิด battery optimization ของ httpSMS (ไม่งั้นระบบปิดแอปตอนจอดับ)
4. เว็บ httpsms.com → **Settings**
   - คัดลอก **API Key** → ใส่ `HTTPSMS_API_KEY`
   - **Webhooks → Add webhook**
     - URL: `https://<โดเมนของเว็บ>/api/sms/inbound`
     - Events: `message.phone.received`
     - Signing key: สุ่มยาว ≥ 32 ตัวอักษร (เช่น `openssl rand -hex 32`) → ใส่ `HTTPSMS_WEBHOOK_SIGNING_KEY`
5. ตั้ง environment บน Vercel (เฉพาะสภาพแวดล้อมที่ใช้ gateway จริง ดู `docs/environments.md`)

| ตัวแปร                           | ค่า                                                                                               | ความลับ? |
| -------------------------------- | ------------------------------------------------------------------------------------------------- | -------- |
| `NEXT_PUBLIC_SMS_GATEWAY_NUMBER` | เบอร์ซิมในเครื่อง gateway เช่น `0812345678` (ปุ่มบนเว็บใช้ และใช้เช็กว่า webhook มาจากเครื่องนี้) | ไม่      |
| `HTTPSMS_WEBHOOK_SIGNING_KEY`    | signing key ของ webhook                                                                           | **ใช่**  |
| `HTTPSMS_API_KEY`                | API key ของ httpSMS                                                                               | **ใช่**  |
| `APP_BASE_URL`                   | โดเมนจริง ใช้ในลิงก์ที่ตอบกลับ (ใช้ร่วมกับ LINE)                                                  | ไม่      |

ไม่ได้ตั้ง `HTTPSMS_WEBHOOK_SIGNING_KEY` = webhook ตอบ 503 · ไม่ได้ตั้ง `HTTPSMS_API_KEY` = สร้างเคสได้แต่ไม่ส่ง SMS ตอบกลับ
`NEXT_PUBLIC_*` ถูกฝังตอน build ต้อง redeploy หลังเปลี่ยนค่า

6. ทดสอบ: ใช้มือถืออีกเครื่องส่ง `SOS FLOOD 13.75,100.50 P2` ไปที่เบอร์ gateway
   → ควรได้ SMS ตอบรหัสเคส และเห็นเคสใหม่ (ป้าย "พิกัดจาก SMS") ในหน้ารายการเคสของกู้ภัย

**ค่าใช้จ่าย:** ค่า SMS ตามโปรโมชันของซิม (ภาษาไทย 1 ข้อความยาวได้ ~70 ตัวอักษร คำตอบรหัสเคสใช้ประมาณ 3 ข้อความ)

## ทดสอบในเครื่อง

ไม่ต้องมีมือถือ — test ยิง webhook ที่เซ็นแล้วเอง และไม่ส่ง SMS จริง (ไม่มี `HTTPSMS_API_KEY`)

- unit: `npm test` (`src/lib/domain/__tests__/sms-sos.test.ts`, `src/features/sms/__tests__/`)
- pgTAP: `npm run test:db` (`supabase/tests/database/tf36_sms_sos.test.sql`)
- E2E: `npm run e2e` (`e2e/sms-sos.spec.ts`) — playwright ตั้ง `HTTPSMS_WEBHOOK_SIGNING_KEY` ค่าทดสอบให้ dev server ที่เปิดเอง
  ถ้าเปิด `npm run dev` ค้างไว้เอง ให้ใส่ค่านี้ใน `.env.local` ด้วย:

```
HTTPSMS_WEBHOOK_SIGNING_KEY=e2e-tf36-signing-key-not-secret
```

## ไฟล์ที่เกี่ยวข้อง

- `src/lib/domain/sms-sos.ts`, `sms-format.ts` — รูปแบบข้อความ ตัวอ่าน ตัวสร้าง ข้อความตอบกลับ
- `src/features/sms/inbound.ts` — ตัวจัดการกลาง (ไม่ผูกกับผู้ให้บริการ)
- `src/features/sms/providers/httpsms.ts` — adapter ของ httpSMS (ตรวจลายเซ็น แปลง event ส่ง SMS) — เปลี่ยนเจ้าเขียนแค่ไฟล์ใหม่ในโฟลเดอร์นี้
- `src/app/api/sms/inbound/route.ts` — webhook
- `supabase/migrations/*_tf36_sms_sos.sql` — ช่องทาง SMS ใน `create_sos_case`, `sms_inbound_messages`, cron ล้างข้อมูล
