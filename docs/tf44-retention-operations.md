# TF-44: การลบข้อมูลหลังปิดเคส

งาน `tf44-case-pii-retention` เลือกเคสจริงที่ปิดเกิน 90 วันทุกคืน โดยไม่แตะเคสจำลอง เก็บข้อมูลที่ใช้คำนวณสถิติและลบข้อมูลติดต่อ สุขภาพ พิกัด ข้อความอิสระ และตัวเชื่อมผู้แจ้ง การปกปิดประวัติเป็นข้อยกเว้นเฉพาะเคสที่ครบกำหนด: เก็บเหตุการณ์และเวลา และเพิ่ม audit เมื่อมีการล้าง การแก้ประวัติทั่วไปยังถูกปฏิเสธ

เมื่อครบกำหนด รหัสเคสเดิมและลิงก์ติดตามเดิมจะใช้ไม่ได้อีก ตัวเลขสถิติยังอ้างอิงข้อมูลเคสที่ปกปิดแล้วได้ ข้อมูลที่เหลือเป็นข้อมูลลดการระบุตัวตน ไม่รับประกันว่าจะไม่มีความเสี่ยงในการระบุตัวตนเมื่อเชื่อมกับข้อมูลภายนอก

ไฟล์รูปต้องลบผ่าน Storage API มิฉะนั้นจะเหลือไฟล์จริงอยู่ใน object storage งานฐานข้อมูลจึงย้ายเส้นทางรูปไปไว้ในคิวส่วนตัวและตัดสิทธิ์เข้าถึงจากแอปก่อน worker ลบไฟล์จริง จากนั้นจึงยืนยันและลบรายการออกจากคิว หากล้มเหลวจะลองใหม่โดยอัตโนมัติสูงสุด 10 ครั้ง ก่อนทำเครื่องหมาย `failed_at` และบันทึก `CASE_MEDIA_PURGE_FAILED` ลง `audit_logs` เพื่อไม่ให้คิววนซ้ำไม่รู้จบ

ก่อนใช้งานในแต่ละ environment ผู้ดูแลต้องตั้งค่าต่อไปนี้ งานล้างอัตโนมัติจะไม่เริ่มหากยังไม่มี URL และ secret ใน Vault; หากตั้งค่าผิด ไฟล์อาจค้างในคิวและยังไม่ถือว่าลบเสร็จ:

1. สร้าง secret แบบสุ่มอย่างน้อย 16 ตัวอักษร และตั้ง `RETENTION_WORKER_SECRET` ใน environment ฝั่งเซิร์ฟเวอร์ของ Vercel โดยใช้ค่าต่างกันสำหรับแต่ละ environment ห้ามใส่ค่าจริงใน repository
2. ตั้ง Supabase Vault `retention_worker_url` เป็น URL HTTPS ของ `/api/retention/media` ที่ชี้ไปยังเว็บของ environment เดียวกัน และตั้ง `retention_worker_secret` เป็นค่าเดียวกับข้อ 1 ห้ามนำค่าจริงใส่แชทหรือไฟล์ใน repository
3. ตรวจว่า `tf44-media-retention-worker` รันได้และไม่มีรายการค้างใน `rls.case_media_deletion_queue` (ทั้งคิวรอและแถวที่ `failed_at` ไม่ว่าง) หลังทดสอบด้วยข้อมูลสังเคราะห์ ดูความผิดพลาดใน `cron.job_run_details` และ HTTP response ของ `pg_net` หากยังไม่ได้ตั้งค่าและมีรูปค้าง worker จะรายงาน error
4. ตารางเวลา `10 19 * * *` คือ 02:10 น. เวลาไทยเมื่อ `cron.timezone` ของ Supabase เป็น UTC/GMT ให้ตรวจค่าจริงของแต่ละ environment ก่อนเปิดใช้ งานประมวลผลไม่เกิน 100 เคสต่อครั้ง และมีงานเก็บเคสค้างทุก 5 นาทีช่วง 02:00–05:55 น.; ผู้ดูแลควรตรวจจำนวนเคสจริงที่ปิดเกิน 90 วันและ `pii_redacted_at` ยังว่าง เพื่อพบ backlog หรือเคสที่ถูกล็อกค้าง

ขอบเขตนี้ครอบคลุมข้อมูลที่โครงการควบคุมในฐานข้อมูลและ bucket `case-media` ไม่ครอบคลุมสำเนาสำรองของผู้ให้บริการ ข้อมูลบนอุปกรณ์ผู้ใช้ หรือข้อมูลที่ส่งออกไปยังบริการภายนอกแล้ว ต้องกำหนดนโยบาย retention ของส่วนเหล่านั้นแยกต่างหาก
